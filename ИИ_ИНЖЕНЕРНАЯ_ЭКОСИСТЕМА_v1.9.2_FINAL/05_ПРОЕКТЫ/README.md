# 05 — Проекты

**Редакция комплекта:** `v1.9.2`

Перед применением project-based HOT сверяй [`РЕЕСТР_ПРОЕКТОВ.md`](РЕЕСТР_ПРОЕКТОВ.md). Начальное состояние реестра — `INCOMPLETE`.

Каждый проект имеет собственный каталог и ровно один канонический файл контекста: `05_ПРОЕКТЫ/<project_id>/PROJECT_CONTEXT.md`.

## Создание проекта

1. Скопируй `03_БАЗА_ЗНАНИЙ/ШАБЛОНЫ/PROJECT_CONTEXT_TEMPLATE.md`.
2. Создай `05_ПРОЕКТЫ/<project_id>/` и сохрани копию под именем `PROJECT_CONTEXT.md`.
3. Используй `project_id` только из строчных латинских букв, цифр, `_` и `-`; запрещены пробелы, `/`, `\\`, `..` и управляющие символы. Пример: `project-alpha`.
4. Заполни `project_name`, `created_at`, `updated_at`. Начальные значения: `status: PAUSED`, `priority: WARM`.
5. Установи `status: ACTIVE` только по явному решению пользователя о том, что проект активен. Для `COMPLETED` также требуется явное решение.
6. Факты о проекте отделяй от планов. Указывай дату/источник состояния, если они доступны.
7. Удали секреты, PII, приватный код и закрытые URL.
8. Добавь/обнови проект в [`РЕЕСТР_ПРОЕКТОВ.md`](РЕЕСТР_ПРОЕКТОВ.md); после любого изменения реестр должен оставаться `INCOMPLETE` до полной ручной сверки всего набора.
9. Передай PROJECT_CONTEXT Router вместе с запросом по этому проекту.

## Правила

- Не смешивай данные разных проектов.
- Не копируй весь проектный контекст в глобальную БЗ.
- В глобальную БЗ переносить только обобщённые и санитизированные знания.
- Project-based HOT разрешён только при `inventory_status: COMPLETE` в `РЕЕСТР_ПРОЕКТОВ.md` и валидном совпадении реестра с каталогом. При `INCOMPLETE`/отсутствующем/невалидном реестре project-based HOT = `UNKNOWN`.
- При полном реестре и ровно одном ACTIVE этот проект даёт project-based HOT без повторного выбора на каждую задачу. При нескольких ACTIVE пользователь выбирает проект для текущей задачи; при нуле ACTIVE проектного основания HOT нет.
- `last_used` отражает подтверждённое фактическое применение контекста в задаче, не чтение файла.
- PROJECT_CONTEXT имеет отдельную YAML-схему; к нему не применяются `main_claim`, `additional_claims`, `maturity` и `lifecycle`.
- Extractor его не создаёт. Sorter только проверяет и предлагает путь; пользователь создаёт/обновляет файл вручную.
