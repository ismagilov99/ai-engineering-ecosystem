# Реестр проектов и полнота PROJECT_CONTEXT

**Комплект:** `v1.9.2`  
**Назначение:** единственный ручной источник для проверки полноты набора проектных контекстов.  
**Владелец актуальности:** пользователь.

## 1. Состояние реестра

```yaml
inventory_status: INCOMPLETE # INCOMPLETE | COMPLETE
last_verified: null           # YYYY-MM-DD; только после полной сверки
verified_by: null             # USER после личной проверки полного перечня
source_commit: null           # Git commit, если Git уже инициализирован; иначе null
projects: []                  # Список всех проектов, включая ACTIVE/PAUSED/COMPLETED
```

**Начальное состояние — INCOMPLETE.** В текущую поставку не импортированы реальные пользовательские проекты и их `PROJECT_CONTEXT.md`; поэтому сборка не делает предположений о полноте проектного списка.

## 2. Когда допустимо поставить COMPLETE

Пользователь может вручную установить `inventory_status: COMPLETE` только после проверки всех условий:

1. Перечислены абсолютно все проекты, которые существуют в этой экосистеме, а не только проекты, нужные для текущей задачи.
2. Для каждого проекта существует ровно один канонический файл `05_ПРОЕКТЫ/<project_id>/PROJECT_CONTEXT.md`.
3. `project_id` внутри YAML совпадает с именем каталога и уникален.
4. Путь из реестра совпадает с фактическим путём; файл читается, его YAML корректен, `status` равен `ACTIVE`, `PAUSED` или `COMPLETED`.
5. Нет неучтённых `PROJECT_CONTEXT.md`, каталогов проектов без записи в реестре или записей реестра без файла.
6. Статус проекта и его запись в реестре сверены вручную с решением пользователя.
7. Заполнены `last_verified` и `verified_by: USER`; при наличии Git указан проверяемый `source_commit`.

В `projects` используется формат:

```yaml
projects:
  - project_id: project-alpha
    path: 05_ПРОЕКТЫ/project-alpha/PROJECT_CONTEXT.md
    status: ACTIVE
```

Не копируй полный контекст в этот реестр. В нём находятся только ID, относительный путь и текущий статус.

## 3. Когда обязательно вернуть INCOMPLETE

Немедленно установи `inventory_status: INCOMPLETE`, очисти `last_verified`/`verified_by` и повторно проведи сверку, если:

- проект добавлен, удалён, переименован или перенесён;
- создан, удалён или перемещён PROJECT_CONTEXT;
- изменился статус проекта;
- обнаружен неизвестный каталог/контекст;
- отсутствует файл или YAML не проходит проверку;
- нет уверенности, что перечень полный.

Сначала обнови реестр, затем вручную сверь весь каталог проектов и только после этого снова установи COMPLETE. Не считай частичную проверку достаточной.

## 4. Как реестр влияет на HOT

- `INCOMPLETE`, отсутствующий, повреждённый или неподтверждённый реестр: проектное основание HOT = `UNKNOWN`; найденный единственный ACTIVE нельзя считать единственным во всей системе.
- `COMPLETE` и ровно один ACTIVE: совпадение `project_id` записи с этим проектом даёт project-based HOT; отдельный выбор проекта на каждую задачу не требуется.
- `COMPLETE` и несколько ACTIVE: пользователь явно выбирает проект для текущей задачи; до выбора project-based HOT = `UNKNOWN`.
- `COMPLETE` и ноль ACTIVE: проектного основания HOT нет.
- Другие независимые основания HOT (свежее подтверждённое применение, criticality, защищённые теги, прямое указание пользователя) действуют независимо от состояния реестра.

Sorter и Consolidator проверяют соответствие реестра и файлов, но не переводят его в COMPLETE от имени пользователя. Они могут только выдать DRY RUN/предложение.

## 5. Ручной порядок обновления

1. Создай/обнови/удали файл проекта вручную.
2. Сразу установи здесь `inventory_status: INCOMPLETE`.
3. Обнови список `projects`.
4. Проверь каждый путь, `project_id`, статус и отсутствие лишних контекстов.
5. Только после полной сверки поставь `COMPLETE`, дату и `verified_by: USER`.
6. Сохрани изменение в Git, если Git включён.

**Текущая поставка:** реестр INCOMPLETE, проектов не импортировано. Это осознанный безопасный default, а не ошибка сборки.
