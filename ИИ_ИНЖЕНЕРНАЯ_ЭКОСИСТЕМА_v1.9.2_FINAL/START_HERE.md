# START HERE — первое подключение ИИ-инженерной экосистемы

> **Назначение этого файла:** дать владельцу и подключаемой ИИ-роли короткий, однозначный порядок первого запуска. Полное описание системы находится в корневом [`README.md`](README.md), а подробное руководство по работе — в [`08_РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ/README.md`](08_РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ/README.md).

## 1. Что перед тобой

Это кандидатная редакция ИИ-инженерной экосистемы `v1.9.2`, собранная на базе `v1.9.1`. В комплект включён единый стандарт документации; поведенческие испытания ролей остаются за владельцем. Она объединяет шесть специализированных ролевых промптов, Методику, файловую базу знаний, входящий контур знаний, проектные контексты, протоколы и пользовательские инструкции. При создании или изменении документации используй [`00_СТАНДАРТ_ДОКУМЕНТАЦИИ.md`](00_СТАНДАРТ_ДОКУМЕНТАЦИИ.md): он задаёт общий голос, но не заставляет все документы следовать одному шаблону.

Комплект имеет статус `CANDIDATE_FOR_VALIDATION` и не является подтверждённой production-системой. Все шесть ролевых промптов зарегистрированы как `CANDIDATE_FOR_VALIDATION`. Текстовая и статическая согласованность файлов не доказывает поведенческую совместимость на конкретной модели. Перед эксплуатацией отдельно проверь поведение каждой роли, межчатовые передачи, multipart-пакеты и запреты на действия без разрешения.

## 2. Первый запуск полного комплекта

Выполняй действия по порядку:

1. **Распакуй ZIP целиком** в отдельную папку. Не извлекай отдельные подпапки из архива: относительные ссылки и структура рассчитаны на единый корень.
2. **Открой корневой `README.md`.** В разделе 2 находится единственный реестр состава, активных версий и канонических путей. Не ищи параллельный `manifest.json` или `MANIFEST.md` — они намеренно не входят в рабочую поставку.
3. **Открой каталог [`02_ПРОМПТЫ/README.md`](02_ПРОМПТЫ/README.md).** Выбери роль по требуемому результату. Не загружай все шесть промптов в один чат.
4. **Создай отдельный чат для выбранной роли** и передай полный файл её активного промпта из `02_ПРОМПТЫ/`.
5. **Передай только необходимые материалы.** Для Router обычно нужны корневой README и описание цели; для Worker — задача и файлы проекта; для Critic — исходные требования и проверяемые артефакты; для ролей БЗ — конкретные источники или записи.
6. **Попроси роль подтвердить входные материалы.** Она должна перечислить, что фактически получила и прочитала, и отдельно назвать отсутствующие источники.
7. **Продолжай постепенно.** Подключай Методику, проектный контекст, индекс, шаблоны и протоколы только тогда, когда они нужны конкретной задаче.

## 3. Какую роль подключить

- **Router** — когда требуется определить маршрут, выбрать роли, разбить большую задачу на этапы или координировать работу системы.
- **Worker / Programmer** — когда нужно исследовать проект, проектировать, писать или изменять код, исправлять дефекты, тестировать и документировать результат.
- **Critic** — когда нужна независимая проверка результата. Для первого независимого аудита используется `BLIND_REVIEW`; для проверки исправлений — `REVIEW_CONTINUATION`.
- **Extractor** — когда из реальных материалов нужно извлечь навыки, практический опыт, инсайты, ошибки, Negative Memory или предложения по улучшению.
- **Sorter** — когда подготовленные записи уже находятся в INBOX и требуют проверки перед размещением. Его режим — DRY RUN.
- **Consolidator** — когда требуется аудит уже существующей базы знаний. Он работает read-only.

Router не обязателен для каждой небольшой и однозначной задачи. Worker допускается запускать напрямую. Аналогично, Extractor не нужен после каждого сообщения, а Consolidator не нужен для каждой новой записи.

## 4. Если запускается только один промпт

Самостоятельный запуск допустим. Передай полный файл нужного промпта и минимально достаточные материалы для его задачи. Без корневого README роль не может подтвердить фактический состав всей экосистемы, версии соседних компонентов, состояние индекса или полноту реестра проектов. Она должна ограничить выводы реально доступными данными.

Самостоятельность промпта не означает, что модель автоматически видит остальные файлы, чаты, Git-репозиторий, облачное хранилище или базу знаний.

## 5. Подключение дополнительных материалов

Используй постепенное раскрытие:

- **Методика:** начни с `01_МЕТОДИКА/README.md` и `КАРТА_МЕТОДИКИ_v5.3.md`; затем передай нужный параграф полной Методики. Краткая Методика и указатели помогают найти материал, но не заменяют нормативный текст.
- **База знаний:** сначала прочитай `03_БАЗА_ЗНАНИЙ/README.md`; затем передавай индекс, нужные записи и шаблоны.
- **Проект:** передай конкретный `PROJECT_CONTEXT.md`, файлы проекта и ограничения. Реестр проектов сейчас имеет статус `INCOMPLETE`.
- **Передача:** используй `07_ПРОТОКОЛЫ/КОНТРАКТЫ_РУЧНОЙ_ПЕРЕДАЧИ.md` и адаптер для нужной пары ролей.
- **Развёртывание или обновление:** используй `07_ПРОТОКОЛЫ/ПРОТОКОЛ_РАЗВЕРТЫВАНИЯ.md`.

Не проси роль применить документ, который ей не передан или который она фактически не открыла.

## 6. Передача между чатами

Между обычными чатами нет общей памяти и автоматической передачи. Пользователь вручную переносит подготовленный пакет, файлы или архив. Получающий чат должен подтвердить:

- идентификатор и назначение передачи;
- фактически полученные файлы и части;
- какие материалы он действительно прочитал;
- отсутствующие или повреждённые элементы;
- известные ограничения и следующий допустимый шаг.

Для больших пакетов используй `transfer_id`, нумерацию частей и итоговый список вложений. Не считай передачу завершённой только потому, что отправитель подготовил текст или архив.

## 7. Границы полномочий и безопасность

- Рекомендация ИИ не является разрешением на действие.
- `AUTO` не даёт права менять глобальные правила, промпты, Методики, схемы, доступы или production-среду без требуемого одобрения.
- Critic не должен исправлять результат вместо Worker.
- Sorter не перемещает файлы и не меняет индекс.
- Consolidator не редактирует базу знаний.
- Extractor подготавливает кандидаты, но не утверждает глобальные правила.
- Секреты, токены, пароли, приватные ключи и ненужные персональные данные нельзя копировать в БЗ или handoff-пакеты.
- Не объявляй тест, аудит, создание файла или передачу выполненными без фактического результата.

## 8. Рекомендуемая первая команда

После подключения Router можно отправить:

> Изучи корневой README и START_HERE. Подтверди версию и статус комплекта, перечисли активные роли и их полномочия, укажи, какие документы ты фактически прочитал и какие пока не подключены. Не загружай всё подряд и не начинай менять системные файлы. После этого прими мою текущую задачу и предложи минимально достаточный маршрут.

Для Worker, Critic и остальных ролей используй их собственные инструкции из каталога промптов. Не передавай эту команду как замену ролевому промпту.
